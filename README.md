# Kestrel Home — Returns Risk Model & Service

Predicts, before dispatch, how likely an order is to be returned — and
recommends CALL, HOLD, or SHIP based on real rupee break-even math, not a
single accuracy number. See `decisions.md` for every judgment call and why.

**Runs entirely locally. No API key, no paid service, no internet
connection needed after setup.**

## Setup

```
pip install -r requirements.txt
```

## Run the full pipeline (in order)

```
python clean_data.py      # dedupe, fix Oct-2025 currency bug, drop leakage columns
python train_model.py     # trains + validates the model, saves model.joblib
python predict.py         # scores test_unlabelled.csv -> predictions.csv
```

## Run the service (API + web page)

```
uvicorn service:app --reload
```

Then open **http://localhost:8000** in a browser — fill in an order's
details and click "Score this order" to see the risk score, recommended
action, and the reasons behind it.

The API endpoint itself: `POST /score_order` with a JSON order (see
`service.py` for the exact fields). If the model hasn't been trained yet,
it fails with a clear message telling you to run the pipeline above first
— it does not crash.

## What's in `predictions.csv`

One row per order in `test_unlabelled.csv`, with a `score` from 0 to 1
(higher = more likely to return) — matches `sample_submission.csv` exactly.

## What the model actually found

- Only **11.4%** of orders are ever returned — Ritu's requested "95%
  accuracy" bar is close to meaningless here (predicting "never returns"
  already scores 88.6% while catching nothing). See `decisions.md` §4.
- Two columns (`last_service_event_type`, `pickup_scheduled_at`) leak the
  outcome directly and were dropped. See `decisions.md` §1.
- **Calling** flagged orders is proven to work and pays for itself on
  almost any above-average-risk order. **Holding** has a real cost (12%
  cancel) and no proven benefit in this data — so the service recommends
  holding only rarely, and never for Shield members. See `decisions.md` §5–6.
